# תוכנית 5א: האוסף השבועי וחישוב הציונים הלילי

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** סקריפט Python שרץ פעם בשבוע ב-GitHub Actions: מוצא את דפי הקורסים של כל מוסד מאושר, מוריד אותם בנימוס, מזהה מה השתנה, מחלץ את הפרטים עם Claude (עם המשפט מהדף ומידת הביטחון), בודק סבירות, ומחליט מה עולה לבד ומה עובר לתור האישור. לצידו, תהליך לילי שמחשב מחדש את הציונים.

**Architecture:**
- **שלב רשת ומודל, ואז שלב כתיבה.** כל ההורדות והחילוץ קורים קודם, בזיכרון. רק כשהם נגמרים כותבים למסד. כך "מודל השפה לא זמין" עוצר את הריצה בלי לשנות כלום (מסמך העיצוב, סעיף 5).
- **ההחלטה ב-Python, הכתיבה ב-SQL.** הלוגיקה (מה השתנה, מה סביר, מה עולה לבד) היא פונקציות טהורות שנבדקות ב-pytest. הכתיבה היא קריאה אחת לכל דף לפונקציה במסד, בטרנזקציה אחת, דרך PostgREST עם המפתח הסודי. אין צורך בסיסמה נוספת למסד.
- **המסד שומר על הכללים.** `course_snapshots` ו-`course_changes` לא ניתנים לעדכון או למחיקה. העמודות שהאוסף רשאי לשנות ב-`courses` הן רשימה סגורה בתוך הפונקציה. כל הטבלאות החדשות סגורות לציבור.
- **קורס חדש נוצר כטיוטה.** `status = 'draft'` כבר מוסתר מהציבור ב-RLS. האישור בתור הופך אותו ל-`active`.

**Tech Stack:** Python 3.12, uv, httpx, BeautifulSoup עם lxml, Playwright ל-Python (Chromium), `anthropic` (`claude-haiku-5-5`, פלט JSON מובנה ב-`output_config.format`), PyYAML, pytest. Supabase (Postgres, PostgREST, pgTAP). GitHub Actions.

**מקור:**
- `docs/superpowers/specs/2026-11-13-course-comparison-part1-design.md`, סעיפים 4 (מבנה הנתונים), 5 (איסוף קורסים) ו-10 (ממשק הניהול).
- `docs/ROADMAP.md`, סבב 5, פריטים 34–36. פריט 36 (רענון מטמון) לא כאן.
- ה-skill `claude-api`: פלט מובנה, טיפוסי שגיאות של ה-SDK.

## איך עובדים בתוכנית הזו

- **תיקייה:** ה-worktree של הסשן. פקודות Python רצות מ-`scraper/` עם `uv run`.
- **מסד מקומי משותף:** הקונטיינרים של Supabase משרתים גם סשנים אחרים. **לא מריצים `pnpm db:reset`.** המיגרציה מוחלת עם `pnpm exec supabase migration up --local`, ובדיקות pgTAP רצות עם `pnpm db:test`.
- **סודות:** המפתחות המקומיים נלקחים מ-`supabase status -o env` בזמן הריצה, ולא נשמרים בקובץ. אין מפתח Anthropic במחשב: מקומית החילוץ רץ במצב הקלטה.
- **בדיקות, במינימום (בקשה של גל):** pytest לחילוץ, לבדיקות הסבירות ולהחלטה. בדיקת אינטגרציה אחת מול המסד המקומי (שלוש ריצות על אתר דוגמה). pgTAP להרשאות ולטבלאות שאי אפשר לשנות.

## החלטות שהתוכנית נשענת עליהן

1. **רשימת המוסדות היא קובץ במאגר:** `scraper/institutions.yaml`. מוסד נכנס אליו רק אחרי אישור של גל, והוא חייב כבר להיות ב-`institutions` במסד. האוסף לא יוצר מוסדות. מוסד שחסר במסד מדולג ומופיע בדוח.
2. **מה עולה לבד ומה לתור (סעיף 5.6), לכל שדה:**
   - **לתור תמיד:** קורס חדש; מחיר שזז ביותר מ-20%, הופיע או נעלם; סילבוס שהשתנה; הבטחה חדשה או שונה של המוסד; שם הקורס (אותו דף יכול להפוך לקורס אחר).
   - **לתור בגלל איכות:** ביטחון שאינו "גבוה"; המשפט שהמודל ציטט לא נמצא בדף; נכשל בבדיקת סבירות; ערך שהיה ונעלם מהדף.
   - **עולה לבד:** כל שינוי אחר (מועד המחזור, מחיר עד 20%, שעות, ימים ושעות, פורמט וכו'), רק אם הוא סביר, בביטחון גבוה, והמשפט נמצא בדף.
   - **שינוי ניסוח בלבד:** אם המשפט מהדף זהה לשבוע הקודם, שדה טקסט לא נחשב שינוי, גם אם המודל ניסח אחרת.
   - **מחיקה בטוחה:** השינוי האוטומטי נכתב רק אם הערך במסד עדיין זהה למה שהאוסף ראה. אחרת הוא עובר לתור.
3. **בדיקות סבירות (סעיף 5.5):** מחיר 50–100,000 ש"ח; שעות 1–3,000; שעות הרצאה או עשייה לא יותר מסך השעות; משך עד 60 חודשים; תאריך מחזור שעבר "חשוד"; סרטון רק מ-YouTube או Vimeo ב-https.
4. **עותק נשמר רק כשהתוכן השתנה.** קריאה בלי שינוי מעדכנת את הדף (`scrape_pages`) ונספרת בדוח. כך `course_snapshots` היא ההיסטוריה של הדף, לבירור מחלוקות (סעיף 6), בלי כפילויות.
5. **טביעת אצבע:** SHA-256 של הטקסט הנראה בדף (בלי סקריפטים, עיצוב, תפריט וכותרת תחתונה) ושל ה-JSON-LD. שינוי בעיצוב לא נחשב שינוי.
6. **נימוס:** בקשה אחת לשנייה לכל אתר, כולל `robots.txt`, מפת האתר והבקשות שהדפדפן שולח לאותו אתר. `Crawl-delay` גדול יותר מכובד. תמונות, גופנים, וידאו ועיצוב נחסמים בדפדפן. השם: `CourseCatalogBot/0.1`, בלי פרטים אישיים. `robots.txt` שלא נטען (5xx או תקלת רשת) או שמחזיר 401/403 נחשב "אסור הכול" לריצה הזו.
7. **מתי פותחים דפדפן:** כשהגדרת המוסד אומרת `render: browser`, או כשבהורדה הרגילה יש פחות מ-200 תווים של טקסט. (בתחילה 400. זה שלח לדפדפן דפים קצרים שנבנו בשרת, והורד בזמן הבנייה.)
8. **"ייתכן שאינו פעיל":** דף של קורס שלא נמצא בגילוי פעמיים ברציפות. רק כשהגילוי של המוסד הצליח ומצא לפחות חצי מהדפים המוכרים, אחרת זו תקלה בגילוי ולא קורס שנעלם.
9. **דף שלא נטען:** נספר. בפעם השלישית ברציפות נכנס פריט לתור.
10. **המודל:** `claude-haiku-5-5`, כמו בבדיקת ההוכחות. מאמץ נמוך, פלט JSON מובנה. ערכי טקסט נכתבים בעברית ובמילים של המודל, עובדה קצרה בלי שיווק. המשפט המקורי נשמר רק בעותק הפנימי.
11. **שגיאות מודל:** חיבור, 5xx, 429 אחרי ניסיונות חוזרים, מפתח שגוי: "המודל לא זמין", והריצה נעצרת בלי לכתוב. סירוב, תשובה שנקטעה או JSON שבור: כשל של הדף הזה בלבד.
12. **אישור, דחייה וביטול:** פונקציות במסד לממשק הניהול שייבנה בהמשך הסבב (`approve_course_change`, `reject_course_change`, `undo_course_change`), רק ל-`service_role`. `course_changes` שומר מי אישר.

## משימות

### משימה 1: המיגרציה, pgTAP ותחילת הפרויקט

- [ ] `scraper/pyproject.toml` עם uv (Python ‎>=3.12), התלויות וההגדרה של pytest (סימונים `db` ו-`live`).
- [ ] המיגרציה לפי הטבלה למעלה. RLS בכל טבלה בלי מדיניות, `revoke all` מ-`anon` ו-`authenticated`, טריגרים של `forbid_change` על `course_snapshots` ו-`course_changes`.
- [ ] `scraper_apply_page(p_run_id, p_page jsonb)` מקבל את ההחלטה המוכנה: `outcome` (`unchanged`, `changed`, `not_course`, `failed`), `snapshot`, `new_course`, `auto_changes`, `queue`. בתוכה: upsert של הדף, עותק, טיוטת קורס, שינויים אוטומטיים עם בדיקת ערך ישן, פריטים לתור (פריט ממתין קודם לאותו שדה מסומן `superseded`), ומונים.
- [ ] `supabase/tests/scraper.test.sql`: הציבור לא רואה את הטבלאות; אי אפשר לעדכן או למחוק עותק ושינוי; שדה מחוץ לרשימה נדחה; שינוי אוטומטי נכתב ונרשם; ערך ישן שלא תואם עובר לתור; אישור, דחייה וביטול.
- [ ] `supabase migration up --local`, `pnpm db:test` ירוק. קומיט.

### משימה 2: נימוס, טקסט וגילוי

- [ ] `politeness.py`: `HostLimiter(min_interval)` עם נעילה לכל אתר (בטוח בין תהליכונים), `RobotsCache` לפי ההחלטה 6. כתובת מקומית (127.0.0.1, localhost) מותרת עם מרווח קטן, לבדיקות בלבד.
- [ ] `pagetext.py`: `extract_page(html, url) -> PageContent(title, text, jsonld, video_urls, links)`, `content_hash`, `needs_browser`.
- [ ] `discover.py`: מפת אתר (כולל אינדקס של מפות, עד 2 רמות ו-50 קבצים) ועמודי רשימה, סינון לפי `include`/`exclude`, אותו אתר בלבד, עד `max_pages`.
- [ ] בדיקות: קצב (עם שעון מזויף), robots (מותר, אסור, 5xx), טקסט (סקריפט ותפריט לא נכנסים, JSON-LD כן, טביעה לא משתנה בשינוי עיצוב), מפת אתר וקישורים.

### משימה 3: הורדה

- [ ] `fetch.py`: `Fetcher.get(url)` עם httpx, robots, קצב, עד 3MB, רק HTML, הפניה רק לאותו אתר. `Fetcher.render(url)` עם Playwright: הקשר עם שם האוסף, חסימת תמונות, גופנים, וידאו ועיצוב, קצב ו-robots לכל בקשה לאותו אתר.
- [ ] בדיקה: דף שנבנה רק בסקריפט מאתר הדוגמה נקרא בדפדפן ונותן טקסט (מדלגת אם Chromium לא מותקן).

### משימה 4: השדות והחילוץ

- [ ] `fields.py`: לכל שדה מ-`courses` שהאוסף ממלא: סוג, סכמת JSON לערך, נרמול והשוואה (רשימות כקבוצה, סילבוס לפי סדר הכותרות, טקסט בלי הבדלי רווחים).
- [ ] `extract.py`: `ClaudeExtractor` (סכמה קבועה, הנחיה שהדף הוא מידע ולא הוראות, מיפוי שגיאות לפי החלטה 11) ו-`ReplayExtractor` (קורא את החילוץ הצפוי מהקבצים).
- [ ] בדיקות: ניקוי תשובה (ערכים מחוץ לרשימה, תאריך שבור, ערך שלא נמצא), מיפוי שגיאות עם לקוח מזויף. בדיקת `live` על 20 הדפים, שרצה רק עם `ANTHROPIC_API_KEY`.

### משימה 5: דפי הדוגמה

- [ ] `tests/fixtures/specs.py`: 20 קורסים מומצאים ב-6 התחומים, עם מוסדות מומצאים ("לדוגמה"). מקרים: מחיר בתשלומים, מחיר מבצע, בלי מחיר, מחזור שעבר, מחיר לא סביר, דף באנגלית, סילבוס בטבלה, סרטון, הבטחת השמה, שני מסלולים, דף שנבנה בסקריפט, דף שאינו קורס, דף עם ניסיון להטעות את המודל.
- [ ] `build.py` כותב את הדפים בחמישה מבנים שונים, את `robots.txt` (עם נתיב אסור), את `sitemap.xml`, ואת השבוע השני: מחיר +10%, מחיר +30%, סילבוס שהשתנה, מחזור חדש, ודף שהוסר.

### משימה 6: סבירות והחלטה

- [ ] `sanity.py`: `check(field, value, today) -> list[str]`, לפי ההחלטה 3.
- [ ] `decide.py`: `decide_page(...) -> PagePlan` לפי ההחלטה 2. קורס חדש: טיוטה עם השדות הסבירים, ופריט אחד לתור עם כל השדות והסיבות.
- [ ] בדיקות: כל שורה בהחלטה 2 וכל בדיקה בהחלטה 3.

### משימה 7: הריצה, המסד והדוח

- [ ] `db.py`: קריאת מצב (מוסדות, תחומים, דפים, קורסים) ובדיקה שהטבלאות קיימות, וקריאות לפונקציות.
- [ ] `run.py`: מוסדות במקביל (4), דפים בכל מוסד ברצף; עצירה כשהמודל לא זמין; כתיבה רק בסוף; `scraper_mark_missing` רק כשהגילוי הצליח; דוח ל-stdout ול-`GITHUB_STEP_SUMMARY`. בלי מוסדות ברשימה: הודעה ויציאה, בלי לגעת במסד.
- [ ] `__main__.py`: `run` (לענן או למקומי), `demo` (אתר הדוגמה, מסד מקומי, מצב הקלטה, שבוע 1 או 2), `check-fixtures` (חילוץ אמיתי מול החילוץ הצפוי, בלי מסד).
- [ ] `test_run_db.py` (סימון `db`): שלוש ריצות מול המסד המקומי: שבוע 1 (קורסים חדשים בתור), אישור, שבוע 2 (שינוי קטן עלה לבד, שינויים חריגים בתור, דף שלא השתנה לא נקרא שוב למודל), ושבוע 3 (הדף שהוסר מסומן "ייתכן שאינו פעיל").
